# Contributing

DADE is in early design work.

Right now, the most useful outside contributions are questions, edge cases, security concerns, interoperability concerns, and feedback on whether the ownership model makes sense.

## Before writing code

Please open an issue first for any substantial change.

That is especially important for:

- deed format changes
- identity design
- transfer rules
- lending
- recovery
- cryptography
- device authorization
- licensing
- compatibility claims

Some technical work may need intellectual property review before it can be discussed or merged publicly.

## Contributions and rights

Do not submit material that you do not have the right to contribute.

Pajic has not published final contributor license terms yet. Substantial outside code or specification contributions may be held until a contributor agreement is in place.

Opening an issue to describe a problem or suggest a direction is preferred for now.

## Writing style

Write like a person.

Use plain English. Keep sentences direct. Explain what something does before reaching for protocol language.

Avoid corporate filler, fake excitement, vague claims, and unnecessary jargon.

Do not use em dashes in project writing.

If a technical term is needed, define it.

## Technical claims

Do not claim DADE solves a problem unless the design actually does.

If a limitation exists, write it down.

If a security property depends on being online, secure hardware, a trusted issuer, or a particular operating system feature, say so.

## Compatibility

Do not describe an implementation as DADE 1 compatible or conformant until the conformance rules and test suite exist.
